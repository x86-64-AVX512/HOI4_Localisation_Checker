HOI4 LOCALISATION CHECKER
=========================

Версия: 0.9.6F5 Beta

Назначение
----------
Программа проверяет локализации Hearts of Iron IV и Equestria at War.
Она работает только на чтение и никогда не изменяет выбранные файлы.

Запуск готовой версии
---------------------
1. Распакуйте архив целиком.
2. Не переносите LocalisationChecker.exe отдельно от папок _internal и fonts.
3. Запустите LocalisationChecker.exe.
4. Нажмите «Проверить файл» для одного .yml или «Проверить папку» для
   рекурсивной проверки всех .yml в выбранной папке.

Пользовательский settings.json не входит в архив обновления и создаётся рядом
с программой при первом изменении настройки. Поэтому распаковка новой версии
поверх старой папки не заменяет сохранённые пути и исключения.

Что проверяется
---------------
- небезопасные символы, отсутствующие во всех подключённых UI-шрифтах;
- повреждённые байтовые последовательности UTF-8;
- отсутствие UTF-8 BOM в начале файла;
- повторный BOM или U+FEFF внутри текста;
- незакрытые кавычки;
- неизвестные escape-последовательности, например \k или \ш;
- повторяющиеся ключи в рамках одного языка;
- возможное повторное перекодирование текста (mojibake).
- прямые кавычки " внутри текстов под заголовком l_russian:.

Прямые кавычки в русской локализации
------------------------------------
На основной вкладке в блоке «Дополнительные проверки» расположен включённый
по умолчанию флажок поиска прямых кавычек. Проверка действует только для
значений под заголовком l_russian: и создаёт предупреждение STRAIGHT_QUOTE
для каждой найденной кавычки U+0022 внутри текста.

Открывающая и закрывающая служебные кавычки строки локализации не учитываются.
Экранированная запись \" считается отображаемой прямой кавычкой и также
попадает в результаты. Кавычки-ёлочки «» предупреждений не вызывают. Двойной
щелчок открывает файл в Notepad++ и выделяет конкретную найденную кавычку.
Флажок можно отключить; его состояние сохраняется в settings.json.

Вкладка «Длина текстов»
-----------------------
Вторая вкладка проверяет длину описаний фокусов, ивентов и основных текстов
вступительных экранов. Для каждой категории можно независимо включить или
отключить проверку. Если выключены все категории, запуск блокируется.

Лимиты задаёт пользователь. По умолчанию установлено 350 символов для фокусов
и 3400 для ивентов и вступительных экранов. Памятка в интерфейсе рекомендует
для русской локализации примерно 345–350 символов для описания фокуса и около
3400 для описания ивента или вступительного экрана. Предупреждение появляется
только после превышения заданного значения.

Для фокусов доступны три взаимоисключающих режима: проверка только длины,
поиск управляющей последовательности \n и точная проверка вместимости через
EaW Focus Text Preview. В режиме поиска \n поле лимита блокируется, длина
фокуса не проверяется, а FOCUS_NEWLINE появляется только при наличии хотя бы
одного настоящего \n. Экранированная запись \\n переносом не считается.

В точном режиме количество символов и заданный порог остаются справочной
характеристикой. Все найденные описания фокусов, в том числе более короткие,
передаются EaWFocusTextPreviewCLI.exe через UTF-8 JSON. Окончательный результат
рассчитывается по настоящим bitmap-шрифтам EaW, ширине xadvance, игровым
переносам и координатам окна фокуса. В таблицу выводятся только фокусы с
красным статусом. Зелёные и жёлтые результаты учитываются только в сводке.

Путь к EaWFocusTextPreviewCLI.exe выбирается пользователем и сохраняется в
settings.json. Нельзя переносить отдельно один EXE: рядом с ним обязательно
должна оставаться папка _internal из полной папки EaWFocusTextPreview.
Точная проверка всегда использует политику visual: жёлтый статус допустим,
красный считается переполнением. Порядок атласов RU/EN настраивается. При
автоматическом выборе язык определяется по заголовку локализации; резервный
приоритет для неизвестного языка задаётся пользователем.

Код FOCUS_PREVIEW_RED содержит количество символов, предварительный порог,
число строк, высоту текста, пересечение с панелью «Эффект» и отсутствующие
глифы. Ошибки запуска или протокола CLI не считаются успешной проверкой:
общая ошибка останавливает точный режим, а ошибки отдельных элементов
показываются отдельно.

Динамические игровые выражения вида [GetSomething] нельзя вычислить вне
запущенной игры. Для таких описаний точность результата ограничена неизвестным
значением, которое игра подставит во время выполнения.

В длину входят видимые статические символы. Цветовые коды, текстовые иконки,
служебные выражения, переменные, динамические вставки и сама запись \n не
учитываются. Если присутствует динамическая вставка, сообщение отдельно
указывает, что измерена статическая часть.

Чтобы отличить фокус от ивента или вступительного экрана, вкладка использует
структуру файлов мода и связи с интерфейсом. Поэтому корневая папка мода
обязательна. Для вступительного экрана анализируются основные текстовые поля
welcome-screen и цепочки scripted localisation, которые они вызывают.

Для каждой роли сохраняется основание: исходный файл, строка, применённое
структурное правило и уровень надёжности. Они отображаются в столбцах
«Надёжность роли» и «Основание роли». Явная ссылка из desc/text считается
подтверждённой; описание, полученное из существующего объекта по правилу
id + _desc, помечается как определённое по структуре.

Один ключ может законно иметь несколько ролей. В таком случае каждая роль
проверяется отдельно и получает собственную строку результата с собственным
основанием. Например, общий ключ может не пройти лимит фокуса, но пройти более
высокий лимит ивента. Программа не выбирает одну роль и не скрывает остальные.

Настройки включённых категорий, режим фокусов, введённые лимиты и параметры
точного модуля сохраняются в settings.json. Двойной щелчок открывает результат
в Notepad++; для FOCUS_NEWLINE выделяется первое найденное \n. Щелчок по
заголовку столбца «Длина» сортирует предупреждения по числу символов;
повторный щелчок меняет направление сортировки.

Вкладка «Сравнение ключей»
--------------------------
Пользователь отдельно выбирает папку английской и папку русской локализации.
Обе папки могут находиться где угодно, не обязаны называться english/russian
и проверяются рекурсивно. Пути сохраняются в settings.json рядом с программой.

В английской папке собираются записи под заголовком l_english:, в русской —
под l_russian:. Затем сравниваются глобальные наборы ключей. Имена файлов и
их расположение на двух сторонах могут различаться.

MISSING_IN_RUSSIAN означает, что ключ существует в английской локализации, но
отсутствует в русской. MISSING_IN_ENGLISH означает обратную ситуацию.
Повторные объявления выводятся отдельно как DUPLICATE_ENGLISH_KEY или
DUPLICATE_RUSSIAN_KEY и не считаются отсутствующим переводом.

Ошибки разбора, которые могут скрыть ключ и сделать сравнение неполным, также
показываются в таблице. Проверки BOM и escape-последовательностей остаются на
основной вкладке и не дублируются здесь.

Результаты можно фильтровать по направлению различия, дублям и ошибкам файлов.
Щелчок по заголовку «Ключ» сортирует видимые строки. Ключ копируется кнопкой,
Ctrl+C или через контекстное меню. После выбора строки доступны отдельные
кнопки открытия английского файла, русского файла или обоих файлов в
Notepad++. Те же варианты появляются по двойному или правому щелчку.

Если ключ существует на выбранной стороне, Notepad++ переходит к его точной
строке. Для стороны, где ключ отсутствует, программа пытается подобрать
парный файл по относительному пути и вариантам имени _l_english/_l_russian и
открывает его на том же номере строки, где ключ найден в существующей
локализации. Если однозначной пары нет, соответствующий вариант открытия
недоступен. Это особое поведение действует только во вкладке «Сравнение
ключей»; на остальных вкладках двойной щелчок работает как прежде.

Выгрузка результатов
--------------------
На каждой вкладке есть кнопка «Выгрузить результаты…». Она сохраняет в CSV
текущее содержимое соответствующей таблицы: только видимые строки и ровно в
том порядке, в котором они расположены на экране. Поэтому фильтр вкладки
«Сравнение ключей» и сортировка по длине или ключу учитываются автоматически.

CSV записывается в UTF-8 с BOM и с разделителем «;», поэтому кириллица и
Unicode-символы корректно открываются в Excel, LibreOffice и текстовых
редакторах. Последняя выбранная папка выгрузки сохраняется в settings.json.

Режимы проверки символов
------------------------
Мягкий режим предназначен для быстрой проверки. Символ считается допустимым,
если он присутствует хотя бы в одном подключённом шрифте. Такой режим может
пропустить много символов, которые не поддерживаются отдельными элементами
интерфейса.

В классическом жёстком режиме символ должен присутствовать в каждом
используемом семействе шрифтов. Он обнаруживает больше потенциальных проблем,
но может давать много ложных срабатываний.

Режим «Жёсткий — контекстный» сначала выполняет классическую жёсткую проверку,
а затем перепроверяет предупреждения UNSAFE_GLYPH по шрифтам реального
интерфейсного контекста. Прямые ключи связываются со шрифтами в interface/*.gui.
Для динамических ключей программа дополнительно анализирует идеи, фокусы,
решения, технологии, технику, события, персонажей, названия партий и стран,
victory points, кодовые названия операций, scripted localisation и другие
движковые конструкции. Для названий на карте учитывается шрифт tahoma_60.

Предупреждение снимается только тогда, когда символ присутствует во всех
шрифтах, которыми этот ключ может выводиться. UNSAFE_GLYPH означает, что
отсутствие символа подтверждено конкретным шрифтом. Если контекст определить
не удалось, такой случай по умолчанию скрывается, потому что отсутствие глифа
не доказано.

Флажок «Показывать неопределённый контекст» возвращает такие случаи отдельным
предупреждением UNKNOWN_FONT_CONTEXT. Настройка сохраняется в settings.json.

Контекстный режим нельзя запустить без явно выбранной корневой папки мода.
Она выбирается кнопкой «Выбрать…» в разделе режимов и сохраняется в
settings.json. Если проверяемый файл находится в другой установленной копии
мода, программа блокирует запуск и просит выбрать правильную версию. Для
отдельного файла вне мода используется указанная пользователем папка.

Стандартная папка Hearts of Iron IV ищется автоматически через Steam.
Найденные стандартные interface-файлы учитываются вместе с файлами мода,
причём модифицированные файлы мода имеют приоритет.

Выбранный режим влияет только на проверки глифов UNSAFE_GLYPH и
UNKNOWN_FONT_CONTEXT. Проверки UTF-8, BOM, кавычек, escape-последовательностей
и повторяющихся ключей работают одинаково во всех режимах.

Исключения символов
-------------------
Кнопка «Исключения…» открывает общий список исключений для всех режимов.
В него можно вставить один или сразу несколько символов. Добавленные символы
больше не вызывают предупреждение UNSAFE_GLYPH.

Проблемный символ также можно добавить через контекстное меню строки результата:
нажмите правой кнопкой и выберите «Добавить символ в исключения». Изменения
применяются при следующей проверке.

Список сохраняется в файле settings.json рядом с LocalisationChecker.exe,
README.txt и папкой fonts. Поэтому при переносе всей папки программы исключения
переносятся вместе с ней. В окне исключений символы можно выбирать и удалять
из списка.

Диагностика
-----------
Каждая найденная проблема содержит полный путь к файлу, номер строки,
номер столбца, ключ локализации и описание. Программа ничего не заменяет
и не предлагает автоматических исправлений.

Чтобы скопировать ключ, выберите строку результата и нажмите кнопку
«Копировать ключ», сочетание Ctrl+C или пункт контекстного меню правой кнопки.

Если выбрано предупреждение UNSAFE_GLYPH или UNKNOWN_FONT_CONTEXT, кнопка
«Копировать символ» и одноимённый пункт контекстного меню копируют в буфер
проверяемый знак.

Открытие в Notepad++
--------------------
Двойной щелчок по строке ошибки или предупреждения открывает соответствующий
файл в Notepad++ и переносит курсор к найденным строке и столбцу. Для
предупреждения о глифе проблемный Unicode-символ дополнительно выделяется.
Та же команда доступна через правую кнопку: «Открыть в Notepad++».

Программа автоматически ищет установленный Notepad++. Если редактор находится
в нестандартном месте, при первом открытии нужно указать notepad++.exe вручную.
Путь сохраняется в переносимом settings.json рядом с программой. Установка
плагинов Notepad++ не требуется.

Флажок «Открывать Notepad++ в полноэкранном режиме (F11)» определяет режим его
окна при открытии диагностики. По умолчанию флажок выключен, поэтому редактор
открывается в обычном режиме. Выбор также сохраняется в settings.json рядом
с программой.

Надёжность настроек
-------------------
Формат settings.json имеет собственную версию. Настройки прежнего формата
обновляются автоматически при следующем сохранении. Если файл был создан
более новой несовместимой версией программы, чекер не станет его
перезаписывать и сообщит об ошибке.

Сохранение выполняется сначала во временный файл в той же папке, а затем
атомарно заменяет settings.json. Если запись или замена прервётся, прежние
настройки останутся целыми.

Повторяющиеся ключи
-------------------
При проверке одного файла ищутся повторы внутри него. При проверке папки
сравниваются все найденные .yml. Одинаковый ключ в разных языках допустим.

Шрифты
------
Папка fonts поставляется вместе с программой. В ней находятся текстовые
дескрипторы .fnt базовой игры и мода. Файлы .dds не нужны: список доступных
Unicode-символов хранится в строках char id внутри .fnt.

Сборка из исходников
--------------------
Игровые .fnt не хранятся в публичном репозитории. Сначала подготовьте их из
своих установок Hearts of Iron IV и Equestria at War командой, описанной в
fonts\README.md. Затем запустите build.bat. Сценарий создаст отдельное
виртуальное окружение, установит PyInstaller, выполнит тесты, проверит
ресурсы, соберёт приложение и создаст архив:

dist\LocalisationChecker-Windows.zip

Для обычного использования Python и самостоятельная сборка не нужны.

Лицензия
--------
Исходный код LocalisationChecker распространяется по максимально
разрешительной лицензии 0BSD. Игровые .fnt, Hearts of Iron IV, Equestria at
War, EaW Focus Text Preview и Notepad++ не переходят под лицензию программы.
Подробности находятся в LICENSE и THIRD_PARTY_NOTICES.md.

LocalisationChecker создан участником проекта Equestria at War, но не
является официальным продуктом Paradox Interactive или команды EaW.
